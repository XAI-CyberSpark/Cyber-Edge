# OAKEgde Studio 开发者文档

这套文档帮助你在本机运行 OAKEgde Studio，理解场景编排的工作方式，修改网页和后端，以及接入模型、节点与 MCP 工具。读完对应章节后，应能找到实现位置、完成操作并判断结果是否正确。

状态：第一版，持续维护。维护日期：2026-10-05。适用范围：当前仓库的智能座舱网页工作台，产品编号以 [VERSION](../../VERSION) 为准。主依据：当前源码、[项目上下文](../../CONTEXT.md)、领域规范与各版本验收。返回[项目主文档](../README.md)。

网页版：[本机开发者文档](http://127.0.0.1:5173/docs)。启动现有 Studio 后访问 `/docs`；内容直接来自本目录及已登记领域文档。网页维护与构建方式见[共同维护](MAINTENANCE.md#网页维护dev92)。

[产品更新](UPDATES.md)按周分条说明变化；需要逐轮追溯时查看[详细开发记录](../../CHANGELOG.md)。

## 从哪里开始

| 你要做什么 | 阅读顺序 | 完成后应能做到什么 |
| --- | --- | --- |
| 第一次接手项目 | 快速开始 → 核心概念 → 工程开发 | 启动前后端，定位一个页面与相关接口 |
| 开发网页功能 | 工程开发 → 测试与排障 | 沿现有组件、状态与样式约定实现并验证变更 |
| 接入模型或工具 | 配置与接入 → API → 测试与排障 | 区分目录、已配置、可执行与已验证，处理真实失败 |
| 调用后端 | API → 配置与接入 | 使用项目版本检查、消费编排事件、调用已登记工具 |
| 维护文档与交接 | 共同维护 → 项目主文档 | 将需求、实现和证据放到正确位置，避免内容漂移 |

## 如何理解文档中的状态

“源码已实现”表示找到了对应逻辑；“已验证”必须带具体环境和验收证据；“规划”不能当作可调用能力。本文档中的命令和示例按源码核对，实际执行过的范围单独记在[覆盖记录](MAINTENANCE.md)。

当前主链路是 React 网页与 FastAPI 后端，包含本地或远端模型接入和座舱体验仿真。实车执行、传感器级物理仿真、任意场景可靠性、通用插件市场均不能从“页面有入口”推定为已完成。
