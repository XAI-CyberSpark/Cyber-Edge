# OAKEgde Studio 节点设计规范

状态：当前视觉规范；公共框架已实施，专项复杂内容的差异见第8节｜维护日期：2026-09-25｜迭代：2.8.0-dev.44

[返回项目主文档](<../README.md) · [全站设计约定](<DESIGN_GUIDELINES.md) · [参数基线](DESIGN_TOKENS.md>) · [节点业务契约](NODE_CONTRACTS.md>)

目的：以CE-21的开始/模型卡片为基准，让每个节点有一致的骨架、清楚的信息层级和可辨认的状态。此规范仅管理画布节点；不改变节点的业务职责、输入输出、执行协议和已有项目坐标。

## 1. 基本结构

从上到下：实际运行状态（存在时） → 图标与业务标题 → 配置/模型摘要 → 简短说明或结果 → 按需展开的详细配置。端口附着在边缘，不参与文字排版。短节点自然收缩，禁止为了等高制造空白。

- 标题讲本节点做什么，类型/模型放次级信息。标题完整换行，不用省略号隐藏业务含义。
- 图标在标题左侧，不在不同节点中左右换位；标题左边界、说明左边界在各自结构内固定。
- 优先呈现一个摘要和必要状态，长提示词、原始输出与详细配置按需展开；警告与关键失败原因不能只藏在tooltip里。
- 用户已有的端口ID、位置、连接方向和节点坐标不因美化改变。

## 2. 尺寸、间距与圆角

以下均为画布缩放100%时的CSS像素；缩放由ReactFlow统一处理，不根据浏览器宽度单独缩小字体或图标。

| 对象 | 统一值 | 使用规则 |
| --- | --- | --- |
| 标准节点宽度 | 280px | 模型、工具、逻辑、数据、车控、互动等共享；不随文字随意变宽 |
| 乘客输入节点 | 240px | 明确的紧凑变体，其余参数相同 |
| 外部内边距 | 四边16px | 状态、标题和正文均在内容区内 |
| 卡片圆角 | 16px | 各类型与各状态一致，不恢复输入胶囊形 |
| 内部信息块圆角 | 8px | 摘要、模型行、表单控件；复杂旧内容迁移见第8节 |
| 图标容器 | 32×32px，圆角10px | 不收缩；图形20×20px；模型允许已有紫色分类强调 |
| 图标到标题 | 12px | 清除旧的额外margin，避免叠加成20px |
| 标题区到正文区 | 12px | 由共享header后的规则控制 |
| 内部间距尺度 | 4 / 8 / 12 / 16px | 4：标签组；8：相关信息；12：内容分区；16：外边距 |
| 模型/摘要行 | 内边距8px、元素间距8px | 长模型名单行省略，完整值通过title及详情保留 |
| 状态行 | 最小20px，下面8px | 实际运行后出现；没有状态不预占空行 |
| 表单控件 | 最小高32px、圆角8px | 宽度不超过内容区；textarea按内容/用途约束 |
| 连接点 | 10×10px，2px卡片色边框 | 保留既有语义、方向和连接行为 |
| 边框 / 焦点 | 边框1px；选中轮廓2px、外移3px | 选中与运行状态并存，不相互覆盖 |

源码唯一公共入口：[node-card.css](../../studio/src/components/nodes/node-card.css)。以`--node-*`局部变量管理，不扩展成全站spacing规则。新节点复用`getNodeFrameClass`和`ce-node-header`，不能再用自定义w-*/p-*/rounded-*抢占共享参数。

## 3. 字体与信息密度

2026-09-26 dev.47：字号统一遵循[TYPOGRAPHY](TYPOGRAPHY.md)，以下更新替代dev.44的14/12/11规格。节点几何和已保存坐标不变。

| 角色 | 字号 / 行高 / 字重 |
| --- | --- |
| 业务标题 | 16px / 24px / 600 |
| 正文、模型名 | 14px / 22px / 400 |
| 副标题、类别、元信息 | 12px / 18px / 400–500 |
| 代码、原始输出 | 系统等宽；13px / 20px，独立滚动 |

沿用系统无衬线，不引入像素字或新的装饰字体。简短说明最多两行，提供完整说明的详情入口或title；正文宽度可收缩，长英文、URL、ID必须换行。不得隐藏错误、确认条件或业务意义以满足两行限制。

## 4. 颜色、状态与交互

- 表面/正文/辅助文字使用`--card`、`--foreground`、`--muted-foreground`；淡色信息块使用`--muted`。保留现有类型图标色，避免每个节点整块上色。
- 默认仅细边框和`0 2px 7px rgb(0 0 0 / .06)`轻阴影；不用强烈外发光表达精致。
- 运行中、完成、失败必须来自真实status，同时有中文标签，不能只靠黄/绿/红颜色。模型失败不得显示成功；没有运行记录不默认绿色。
- 浅色状态边框：运行`#b57b19`、完成`#39805c`、失败`--destructive`；深色运行`#e3bb69`、完成`#80bf9b`。选中始终保留`--ring`轮廓。
- 状态变化仅150ms边框/阴影过渡；不改变卡片比例、不跳动；减少动态效果时关闭过渡与状态呼吸。
- 表单、摘要展开、按钮保留键盘焦点；内部交互用`nodrag`，滚动区域用`nowheel`避免带动画布。
- 不复制参考图中未接入的加号、成功勾选或计时值作为装饰。端口点击热区扩大需单独验证连接，不在本轮改写命中范围。

## 5. 节点之间的留白

这是**新建/整理画布的布局规范**，不是自动重排已有项目的功能声明。

- 默认从左到右，同级标题区顶边对齐；同列使用一致宽度。
- 相邻列边缘间距推荐80px，最低48px；行与分支之间推荐48px，最低32px。
- 外围留白至少32px。按实际卡片包围盒计距，展开详情后重新检查遮挡，不能只比较position坐标。
- 以8px为排列步长；普通节点宽280px时，新列起点推荐增加360px；输入宽240px时仍按真实右边缘留白。
- 分支标签靠近对应端口，避免穿过文字；连接线绕开卡片主体。复杂分支优先增加留白，不能压缩正文解决拥挤。
- 用户手动移动与已有保存坐标优先；本轮不强制吸附、不自动重排，不把推荐值写成已有布局算法。

## 6. 类型差异的边界

输入采用紧凑宽度；模型有模型行/提示词详情；图像/视频保留证据预览；车控保留可修正配置；持续互动保留当前章节与等待/暂停信息。它们共享外壳，内部信息按实际职责变化，不强制所有节点都变成模型卡片。

不得借样式修改删除功能、把仿真标识换成实时、或把占位能力描述成已实现。节点职责仍以[NODE_CONTRACTS](NODE_CONTRACTS.md)的“草案/实现”边界为准。

## 7. 新增/修改节点的验收清单

1. 使用公共外壳、header、图标和token；默认、选中、运行、成功、失败均可读。
2. 检查浅/深色、长中文标题、长英文模型名、空配置、多行错误、展开详情；不溢出、不盖住端口。
3. 检查100%以及常用缩放；窗口变化通过画布平移/缩放呈现，不偷偷重排已有节点。
4. 检查选择、拖动、连接、表单编辑、键盘焦点、滚动与减少动态效果。任何影响连接逻辑的变更应增加对应功能测试。
5. 分别记录模拟数据与真实运行检查；视觉通过不能证明推理、硬件或车控执行成功。

## 8. 实施范围与待收敛项

dev.44：当前17种注册节点共享外壳/显式header（含输入和输出），模型与输入细化；统一外部几何、标题层级、图标框、端口外观、选中轮廓。旧的部分内部元信息仍有9/10px、专用状态小徽标和不同内层圆角，暂不宣称所有复杂内容已完全迁移。后续修改相应内容时按本规范收敛，不能通过全局选择器粗暴放大视频叠层和所有图标。

节点间推荐距离已定义；现有生成器、模板和历史项目尚未统一到该布局规范。全部节点真实运行、所有复杂展开状态、全站无障碍对比度和触屏命中区不属于本次完整验收。具体证据见[dev.44验收](releases/2.8.0-dev.44/ACCEPTANCE.md)。
