## 1. 产品判断与定位

OAKEgde Studio 是面向智能座舱产品经理和体验设计人员的场景定义、可视化编排与体验验证工作台。用户描述场景，明确触发与反馈，通过节点流连接模型和车辆能力，使用文字、图片或模拟信号观察 HMI 与车辆状态，再把结果交给研发。

核心价值：让“我想要怎样的座舱体验”变成“能运行、能解释、能验证的场景”。车模是反馈载体；模型提供感知判断；节点流承载规则；运行证据支持验收。平台的价值不能只用界面真实感衡量。

当前产品判断：已有可运行工程原型，尚不具备稳定的首版交付闭环。主要短板为信息架构、草稿与版本保护、能力就绪提示和可追溯验收，而非缺少更多展示组件。

首版建议交付：Windows 本地运行的座舱体验验证工作台、两类标准场景、可导出的运行证据。真实车端部署作为独立后续里程碑，不阻塞本地体验验证版。此发布边界是本 PRD 提案，需产品负责人确认。

## 4. MVP 范围与非目标

P0：场景新建/保存/恢复，清晰导航，结构化规格，可编辑节点流，依赖检查，文字/图片/模拟信号输入，真实执行反馈，正常与异常分支，运行证据导出。

P1：场景修订历史比较、测试集批量执行、可配置模型连接管理、模型输出诊断、资源与模板搜索。基本模型选择和连通性检查属于 P0，完整管理中心属于 P1。

非目标：自动驾驶决策、真实车辆控制、传感器精度验证、连续视频风险跟踪、生产级 TTS/ASR、多人协作权限、云端运营平台、无人机/机器人、独立地图导航和音乐服务。保留已有代码不等于纳入本轮验收。

视觉模型不可用时仍可完成工作台与确定性行为测试；模型 mock 只能作为明确标记的测试输入，不能伪装成图片识别成功。

## 5. 对象与信息架构

- 场景：用户的核心工作对象，包含目标、规格、工作流、依赖和验收条件。
- 工作流：场景的可执行图。MVP 一个场景对应一份主工作流，避免无需求地引入多层管理。
- 项目：现有文件集合概念。MVP 暂不新增项目—场景复杂层级；旧“项目库”可兼容存储，界面逐步统一为“我的场景”。
- 模板：可复制的场景起点，复制后独立编辑，不覆盖来源。
- 场景修订：一次保存的可定位内容版本，与产品软件版本分开。
- 运行：关联某个场景修订、输入、初始仿真状态、模型配置和执行记录。

建议布局：左侧为我的场景、场景模板、模型与设备；当前场景顶部为定义、编排、验证、部署；组件库/变量/节点配置/运行详情属于工作区工具，不与全局导航并列。

移除左侧重复的流程审查、仿真测试、发布管理入口，或迁移为有明确独立职责的全局页面后再恢复。“安全规则”并入场景规格和验证检查；无对应内容的入口不可呈现为正常可用。

固定显示场景名称、当前阶段、保存状态。新建进入定义且保留其他标签；打开场景不静默替换脏标签。顶部切阶段和其他入口必须调用同一行为；高亮由实际状态推导，不单独维护矛盾状态。

## 6. 核心流程

1. 我的场景 → 新建或复制模板，填写场景名称与目标。
2. 定义 → 补齐触发、输入、预期行为、异常处理和验收条件；确认规格。
3. 编排 → 生成或编辑节点图，选择模型与执行能力，检查缺失配置。
4. 验证 → 设置初始条件，输入文字/图片/模拟信号，执行后查看命中路径及实际反馈。
5. 不符合预期 → 回到相应节点修改；旧运行记录保留但标记不适用于最新修订。
6. 保存修订并导出验证记录；满足独立部署门槛后才进入构建。

允许自由回看阶段；阻止的是不满足条件的执行/部署动作，而不是浏览。每个阻塞项必须给出原因和直达修复入口。

## 7. 功能需求与验收

| 编号 | 优先级 | 目标行为 | 可验收标准 |
|---|---|---|---|
| CE-001 | P0 | 统一导航与入口 | 每个可用入口有实际结果；新建进入定义；阶段与选中状态一致；旧标签仍可恢复 |
| CE-002 | P0 | 保存、草稿恢复与离开保护 | 保存成功才显示已保存；失败保留脏状态；刷新、返回首页、重启后可恢复最近草稿；关闭未保存内容提供保存/放弃/取消 |
| CE-003 | P0 | 场景规格 | 目标、触发、输入、动作、失败反馈、验收条件可独立编辑；生成前标出缺项；重新生成前明确是否替换图，支持取消 |
| CE-004 | P0 | 编排与静态检查 | 检出无输入、孤立节点、无效连线、缺失模型和非法参数；节点业务名与底层类型分开；异常定位到节点 |
| CE-005 | P0 | 模型就绪检查 | 展示所选模型和来源；运行前检查可访问性与图像能力；失败指出模型名、原因和配置入口；不把文本回退当视觉结果 |
| CE-006 | P0 | 图文与模拟输入 | PNG/JPEG/WebP 最大 5MB，预览/移除/解码失败反馈；图片无强制视角标签；文字支持中文输入法；执行中禁止重复发送 |
| CE-007 | P0 | 可解释执行 | 运行显示输入摘要、当前节点、分支、动作请求与实际结果；失败不会在 UI 标为成功；同一车辆不被并发动作覆盖 |
| CE-008 | P0 | 共享仿真状态 | 手动和工作流车窗操作进入同一执行器；卡窗返回实际开度与失败原因；HMI 不仅播放预设成功动画 |
| CE-009 | P0 | 儿童关怀单帧判断 | normal/risk/unknown 和数字置信度经校验；高置信危险才警示；静态图片不宣称实时监控或自动风险解除 |
| CE-010 | P0 | 运行证据与结果 | 导出关联场景修订、输入摘要、模型来源、初始状态、执行轨迹、预期/实际和判定；人工判定与自动断言分别标记 |
| CE-011 | P0 | 能力与发布信息真实 | 已实现、模拟、未配置、未验收有区分；未经测量的延迟/包大小显示未测量；禁用入口说明原因 |
| CE-012 | P1 | 场景修订与比较 | 查看保存历史，恢复为新修订；不抹去已有历史；修订变更后旧测试明确标为过期 |
| CE-013 | P1 | 模板与资源整理 | 儿童关怀统一模板来源，标记依赖、适用范围、示例/可用状态；移除当前范围外的主入口 |
| CE-014 | 后续 | 受控部署交付 | 构建前验证图/依赖/目标设备，默认仅当前场景；产物记录提交、依赖与校验值，提供安装与恢复说明 |

## 8. 标准场景与分支

### SCN-001 儿童关怀

输入为用户主动上传的一张图，可以附加文字，但附加文字不能成为检测到儿童的证据。模型输出 status、confidence、risk_action、summary；字段与置信度范围必须校验。默认判断阈值 0.85 是产品初始配置，不是已经标定的识别精度；需模型工程师用样本集评估。

| 条件 | 预期响应 | 禁止行为 |
|---|---|---|
| risk 且置信度达到阈值 | HMI 显示本次图片与风险提醒；右侧同源反馈 | 自动关窗、开门或执行未在场景定义中的车控 |
| normal 且置信度达到阈值 | 提示本次图片未见明确危险行为 | 承诺儿童绝对安全 |
| unknown 或置信度不足 | 提示无法可靠判断，建议补充清晰图片 | 使用模板预设的危险结果 |
| 服务不可用/超时/格式无效 | 本次失败，定位视觉节点，不执行下游动作 | 以文字规则或 mock 冒充视觉识别 |
| 用户手动收起画面 | 仅隐藏图片，本次结果保留 | 宣称风险已经解除 |

真实视觉验收样本至少覆盖明确危险、正常坐姿、模糊/遮挡、非儿童/非座舱图片；由产品负责人提供可用样本，模型工程师审核标签。准确率目标在完成基线评估后决定，不虚设已达标数字。

### SCN-002 雨天关窗

打开部分车窗 → 注入下雨 → 主动运行 → 关闭车窗 → 检查实际反馈。正常全部到 0；注入右后窗卡住时该窗保留实际位置、其他窗完成，并提示具体失败窗。晴天或已经全部关闭不重复执行。复位取消未完成动作并恢复初始状态。此流程验证可复用执行器，不依赖视觉模型；不声称持续订阅天气。

## 9. 状态、错误与记录

场景保存状态：未保存 / 保存中 / 已保存 / 保存失败。检查状态：未检查 / 有阻塞 / 可运行。运行状态：待执行 / 执行中 / 已完成 / 失败 / 已取消（取消能力待实现）。这些状态不可用单个“成功”徽标替代。

处理故障的节点执行成功，不代表原动作成功：例如卡窗后成功发出提醒，运行记录仍须保留车窗失败。运行完成不等于验收通过。

最小数据：scenarioId、revision、spec、graph、modelConfigRef、runId、inputKind、输入引用或摘要、initialState、events、actualState、expected、verdict、timestamps。模型版本不可获取时标记未知；不得伪造。图片默认仅用于当前会话，导出原图需用户明确选择。已有运行记录含图片时需梳理其存储边界，实施与文档一致。

## 10. 非功能要求

- 支持 Windows 桌面浏览器，目标布局 1280×720 及以上；较小宽度可折叠工具，不遮挡主要操作。
- 常用操作可键盘完成，有明确名称、可见焦点；图标不能仅靠颜色表达状态。进入/关闭面板焦点返回触发点。
- 普通本地点击建议 300ms 内显示状态反馈；模型请求建议 30 秒可配置超时，最终阈值由模型性能确定。当前实现不宣称已达到这些指标。
- 生成与模型调用显示进行中和可恢复错误，不展示虚构进度或性能数字。后续取消必须中止/隔离旧结果，防止污染新运行。
- 模型密钥不进场景 JSON、日志和导出包；图片中的文字视为输入内容，不能更改执行权限；只允许已配置动作。
- 不以静态图片判断替代真实安全系统；本地体验验证结论不能表述为整车安全认证。
