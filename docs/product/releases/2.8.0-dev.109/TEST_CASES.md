## 请求结构与预算边界

case可选的 `request_context` 只允许 `conversation_history`、`current_project`、`acceptance_tests`。06提供24条原创对话，07提供原创3节点/2边夹具；其他可执行例只提供锁定计划。所有请求必须固定 `save_on_success=false`、`overwrite=false`。套件的 `runtime_profile=rain/window` 仅兼容现有枚举，独立回放必须使用调用方计划，不能借用旧雨天/车窗场景模板。

最初预登记最多10个HTTP编排请求，每例1次，串行，首探针计入同批。首次协议故障后在下节明确修订为原探针保留、修后正式10例另批冻结；没有挑较好随机样本替换失败。每请求最多8次编排模型调用、3轮构图、3次内容审查；阶段输出额度16384/32768/8192，编排总期限720秒，批测HTTP期限900秒。独立回放真实模型额度0，确定性图仍实际执行；有LLM的图须如实保留该额度下的未完成。

执行者启动前冻结的预算文件位于 `.demo-runtime/optimization-dev109/ten-case-environment/budget.json`。本次登记上限为 **120次模型调用、600,000个预留或已知token、10,800秒**，policy为 `disposable-per-call-pre-reservation-v1`。这些是隔离实验的运行边界，不是产品默认额度；文件配置存在本身不证明门禁已执行，实际计数、拒绝与最终用量以运行证据为准。套件JSON只登记边界和待补manifest，未实现硬累计token门禁。

每次编排可能包含多次规划/构图/核验及生成内图试跑，因此10个请求不是10次API调用。全部成功、失败、返工、截断、图内模型调用均计入批次预算；达到上限停止后续并保存已得证据，不切模型、不追加重抽样。独立回放/审阅额外消耗另列。模型、思考设置、源码身份、服务端口和预算由执行者在run manifest冻结；本预登记不以更换模型或思考设置解释优化收益。

没有核对当日价格与完整真实usage，金额保持未知；usage缺失保留unknown与已知下限。没有同模型/配置的配对基线，不能计算60%节省、每成功成果成本改善或p95变化。成功数为0时每成功成果成本未定义。
