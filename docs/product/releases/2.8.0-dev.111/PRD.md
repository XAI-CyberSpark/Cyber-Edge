## 目标与边界

用户要求：“先做一轮意图理解与改写，并附上原有的描述，之后再选中需要的能力；取得能力不用预算机制，而是使用阈值选取topk。” 当前原始历史先检索、同一次理解选择能力的流程无法在检索前排除撤回意图。dev.110 五例七项漏项的直接原因是候选6000字符裁剪；描述短、否定/历史词参与排序仍是待量化因素。

本轮交付现有 bounded 编排的明确阶段顺序与本地筛选政策，不增加能力、场景关键词特判、查询改写专用模型或向量数据库。每项有效需求单独检索，再合并，不用全局Top-K再次截断。原文、来源引文、数值、位置、否定、更正、真实/仿真条件继续供选择和构图核对。不得把“冷一点”自行改为24度或降低2度。

## 技术合同与取舍

`IntentUnderstanding` 包含 `brief: ScenarioBrief` 与 `queries: [{requirement_id, query: string|null}]`。understand输入当前描述、用户历史、项目结构摘要，不提供能力候选或完整目录。本地检索只使用当前有效改写，原文附在后续上下文与需求来源中，不将包含撤回/否定词的整段引文重新拼入查询。

select输入锁定brief、queries、对应原始描述、分需求检索记录、去重候选、完整注册短目录和当前来源/权限事实，输出既有CapabilitySelection。正常生产增加一次独立选择请求；总上限保持8，因此不声称token或耗时已经减少。构图/修复/审查继续使用既有严格契约及未执行不可应用的产品门槛；本轮测试范围只核对编排，不以执行成功替代编排质量。

筛选参数是内部可测试参数 `min_score=0.35, top_k=32`。相对分为 `RRF / 本次最高RRF`，范围0–1，表示查询内部排序强度，不是语义正确概率；弱查询也会有最优项为1。并列按ID稳定排序并遵守普通K上限；显式身份/已有引用可超K并单独登记。阈值/K不能作为缺口或授权依据，完整目录可见性仍保留。默认值是保守初始政策，不能依靠已打开的回归集调参宣称总体99.9%。

自定义completion适配器的旧纯brief/PlanningResult保持兼容，并在报告标明旧协议；只有新理解合同走拆分阶段。真实生产必须新合同，不能因模型输出旧形状绕过select。正常路径、新合同无效/选择无效、纯约束、多目标、查询无证据、降级、精确ID和已保存引用均需回归。
