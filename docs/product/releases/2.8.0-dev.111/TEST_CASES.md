## 失败定位与后续项

- **07编辑范围**：除fixture_output.data.responseText外，project.id被改成项目名；新增两处edge.type、两处node.data.status、file_name/updated_at与八处meta字段。节点ID/坐标及原业务字段保留不足以满足“其他字段全部保持”。实际宿主规范化也属于此次产物，不能只相信coverage的保持声明；后续须分开检查模型输出与宿主规范化。
- **08缺口协议**：build及两次repair均识别未接入真实执行器/回执，但填入未登记的real-vehicle-hvac-actuator/receipt身份，合同解析拒绝后落入重复构图修复，最终只在元数据/选择诊断保留具体缺口，issues为通用解析提示。应处理已确认外部缺口的合法结构及终止反馈。
- **09回执来源与处置**：首轮capability_need后，两次repair返回草稿；input_booking_request允许用户填real_tool_receipt_received和receipt_source，logic_receipt_gate仅判断这些字段，true分支输出“行程预订已完成。”。没有真实MCP调用或回执生产者，注释“不可达”和designOnly阻断不能修正该来源契约。原所需来源od109-trip-write-fixture/book_trip保留，但最终needs_changes也未满足capability_gap。

本轮只测评并记录以上问题，没有修改生产逻辑、阈值或测试金标，没有重抽或扩大样本。已知十例不足以验证总体99.9%，也不能依据与dev.109不同停止点的结果宣称严格配对提升或费用节省。
