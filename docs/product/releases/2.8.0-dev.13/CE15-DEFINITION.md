# CE-15：五个监控模块的产品定义草案

版本：2.8.0-dev.13 的需求补充；本次只定义，不实施页面或导航。来源为飞书第15项 revision 425、用户截图及当前源码；不是五页完整视觉验收。

## 结论

保留五类用途，名称改为运行记录、设备连接、上下文与记忆、安全校验、运行性能。它们不应各自复制一份日志、硬件状态或安全结论；共用运行ID、数据来源与时间。建议五个入口位于左侧导航下方的运行诊断分组，替代系统监控入口及顶部五标签，不再增加一层选择。低频诊断与项目库/组件库/场景库用分隔线区分。

## 五个模块

| 原名 → 建议名 | 用户要回答的问题 | 保留内容与页面主体 | 删除或合并 |
|---|---|---|---|
| 遥测 → 运行记录 | 刚才为什么成功或失败？ | 按次运行的时间线，状态、耗时、输入摘要，展开查看节点和错误；可筛选当前项目/本次运行 | 不把传感器负载、内存容量全塞入日志；与仿真详情共用记录 |
| 硬件层 → 设备连接 | 输入与动作通道接通了吗？ | 摄像头、麦克风、车辆接口、模型/语音服务列表，状态、来源、更新时间、错误及详情 | 删除常驻安全护栏和CPU类指标，分别归安全校验和运行性能；未接入雷达/V2X等不显示假在线 |
| 记忆 → 上下文与记忆 | 模型本次参考了什么？ | 本次实际上下文条目、来源、检索命中与使用位置；未使用时明确空状态 | 不把RAM和显存称为记忆；移除固定知识图谱数量、固定Milvus规模和随机Token计数 |
| 安全 → 安全校验 | 哪条规则放行、阻止或需要确认？ | 与本次运行绑定的规则结果、触发依据、处置及可追溯事件；未配置/未评估明确显示 | 与硬件层安全状态去重；车辆执行保护仍由原执行器落实，不能由页面绿标代替；不恢复已删除的无功能安全入口 |
| 内核 → 运行性能 | 慢在哪里，资源是否够？ | 实测CPU/RAM、可用的GPU指标、推理耗时/Token；模型和运行关联详情 | 去掉假NPU、固定16GB换算、模拟队列进度。GPU为0不能回退随机NPU，未知显示未采集 |

## 当前证据与重复

FlowCanvas.tsx 初始化设备在线、记忆规模和安全策略，并定时随机更新摄像头FPS、总线负载、记忆Token及内核调度。MiddlewareMonitor.tsx 又重复显示安全护栏。KernelMonitor.tsx 请求 /v1/system/status，但混用模拟值，将GPU使用率映射到NPU且按16GB换算内存。因此“保留用途”不等于认可现有指标为真实能力。运行日志也包含仿真/初始化事件，需要标明来源。

用户截图可见：FPS/延迟和CAN负载保留大量小数，窄卡片内换行割裂数值；连接状态、安全状态与性能挤在同页，信息优先级不清晰。其余页面的具体视觉问题尚未逐页截图验收，本稿只根据代码定义其边界。

## 页面规范（待实施）

导航点击直接切换工作区内诊断页面，保留当前项目和画布状态；顶部保留项目名及返回编排/仿真。避免继续把复杂内容压在窄抽屉。页面共同结构：标题与数据来源 → 最多3个关键概览 → 单个主列表/时间线 → 按需展开详情。标题20px，卡片标题14px，正文14px，辅助12px，页面24px边距，区块16px、卡片内16px。状态颜色只用于异常与选中；单位与数值同排，百分比/延迟最多1位小数，计数整数，长标识截断并可查看全文。无数据、离线、加载失败、模拟数据分别表达，不用随机数装饰。

## 后续实施顺序与验收
