# 2.8.0-dev.2 — HMI 车辆行为仿真

状态：用户已确认方向，开发验证版本。日期：2026-09-11。

## 用户问题与目标

用户希望将围绕车辆空间搭建的仿真展示，调整为参考视频中的车机 HMI：中间有可交互车模，周围是车辆控制和助手反馈。工作流的动作需要实际改变模拟车辆状态，并收到成功或故障反馈。

确认的首个闭环：注入下雨 → 工作流判断 → 关闭车窗 → HMI 与车模变化 → 核对实际状态；卡窗时保留实际开度并提示失败。

## 非目标

物理车辆动力学、传感器准确率、真实车端适配、地图路线引擎、媒体播放器、真实语音助手。该版本是体验级行为模型，不是硬件级车辆仿真。

## 场景 SCN-RAIN-001

- 前置：本地仿真车辆已挂载，至少一个车窗开度大于 0。
- 输入：测试台天气状态 clear/rain；读取四窗实际开度。
- 触发：用户注入天气后主动运行当前工作流。此版本不是持续订阅天气的自动触发服务。
- 条件：weather 为 rain 且存在开启的车窗。
- 动作：四窗目标设置为 0，执行器随时间更新开度。
- 反馈：success、actual、failedWindows、reason；完成后才返回。
- 故障：卡住的车窗不运动，其余车窗正常执行。已达到目标的卡窗不视为本次执行失败。
- 判断：成功和失败为互斥分支；失败动作标记 error，下游判断和提示正常执行。
- 重复：下雨但所有车窗已关闭时，不发出关窗指令。
- 复位：清除故障与上次动作结果，天气恢复晴天。

## 交互

进入任意工作区 → 仿真 → 测试台 → 新建「雨天自动关窗」→ 全部打开 → 测试台注入下雨 → 运行当前工作流。

失败演示：在全部打开之后启用“注入右后窗卡住”，再运行。若先注入卡窗再打开，故障窗本来就是关闭状态，不会产生关窗失败。

同一工作流内切换审查与仿真保留模拟状态；刷新页面或切换到新工作流会建立新的模拟会话。场景 JSON 保存工作流，不包含完整模拟快照。

## 仿真输入面板补充

REQ-008：左侧保留 HMI，右侧为乘员对话/摄像头输入，独立于需求创作聊天。文字或图片触发当前工作流，记录本次车机回复及执行事件。选择摄像头视角随图片说明一起进入模型输入（不是硬件摄像头路由）。上传 PNG/JPG/WebP，最大 5 MB，发送前预览并可移除。空工作流与推理失败明确提示。

本轮继续归入 dev.2。图像 LLM 推理不可用或结构化解析失败时禁止使用文字规则推断车辆动作。识别准确性依赖用户配置的工作流与视觉模型；上传和流程完成均不表示识别成功。对话记录为当前仿真页面会话，最多保留约 20 条，切换工作流或离开仿真页清空；未实现跨轮模型记忆。
