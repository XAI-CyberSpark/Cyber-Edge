# 连续语音交互

2026-09-23，dev.22 开发迭代。交付为现有 HMI 的本地交互优化。

用户目标：点麦克风后开始听，说话文字出现在原圆角矩形；一句话结束后自动给出回复、追问或车辆建议，不要求手动停止、编辑、发送。

- REQ-01：用户点击才申请麦克风；真实收音驱动 Bloub 聆听姿态，权限等待不伪装为已聆听。
- REQ-02：说话期间识别结果更新在原入口，允许后续修正。保持纯黑、Bloub、原布局；两行文字可滚动查看，自动跟随最新文字。闲置仍只显示 CYBER 助手和麦克风。
- REQ-03：短暂停顿继续听；检测约1.1秒静音自动停止，最终转写只提交一次；回复/追问/确认卡片就绪后展开。已有车辆确认与实际结果反馈保留。
- REQ-04：8秒无有效声音退出，30秒上限，手动结束/Escape/页面隐藏/卸载释放麦克风，迟到结果不能回填或执行。服务失败显示真实错误。

实现边界：复用 SenseVoiceSmall INT8，每约0.75秒对累计音频做滚动增量识别，请求串行、繁忙时跳过中间快照，不建立等待队列；不是原生流式 ASR。端点采用浏览器降噪后的本地音量/持续时长启发式，不判断语义是否完整。模型与网站/API架构不变，不增加播报、唤醒、常驻监听或独立展示页。音频仅存在内存。

验收场景：说“空调调到二十三度”→文字逐步出现→停顿后自动理解→空调建议→确认前温度不变→确认后23°C。另覆盖中途取消、句内停顿、无声、故障和重复结束。
