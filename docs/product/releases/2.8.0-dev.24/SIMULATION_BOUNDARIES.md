# CE-19 仿真功能分区草案

来源：飞书revision580第19项，用户要求先定义分区。本稿待确认，未据此修改执行和反馈路由。

## 右侧：测试台（面向测试者）

负责提交图片、文字、场景参数等测试输入，记录每次用例的输入、开始/完成/失败、预期与实际反馈；错误详情、模型/接口故障、超时、原始输出、节点轨迹和重试入口放在这里或对应运行记录。输入是测试用例，不包装成车内用户聊天。成功请求不等于场景通过；未配置断言不能显示测试通过。

## 左侧：HMI体验区（面向车内用户）

显示场景真正面向乘员的提醒、助手对话、需要确认的操作及仿真执行器实际反馈。模型中间推理、接口错误堆栈和测试日志不进入中控屏。车辆仍为仿真；“真实用户反馈”指符合产品交互流程，不代表实车接入。

## 输入与输出规则

- 右侧提交用例→工作流执行→显式的用户反馈/车控输出节点→HMI；后台诊断独立写入测试台/运行记录。
- 模型超时/不可用/JSON格式错误：用例失败，只在测试台说明具体原因；HMI结束该次处理中状态，不展示技术错误，不伪造成功或正常判断，不执行未确认动作。
- 模型成功判定“无法判断”：是有效的业务结果；是否提示乘员由场景反馈节点决定，不等同技术失败。
- 用户直接在HMI说“打开车窗”：该入口代表车内用户。若服务不可用，建议只给简短“暂时无法完成，请稍后重试”，技术原因留在测试台；避免用户误以为车窗已打开。该降级文案待确认。
- 主动提醒由有效场景输出触发；重复测试不重复堆叠。旧结果不能冒充本次结果；安全提醒何时解除须由场景规则决定，不因技术失败自动解除。

## 实施检查点（待确认后接线）

GraphEngine.executeNode的catch当前直接写hmi.message/hmi.alert，导致技术失败进入HMI。需要拆成“运行诊断事件”和“面向用户反馈事件”，同时调整右侧“你/车机”等聊天标签为“测试输入/运行结果”。CockpitAssistant的直接对话失败路径单独处理，不能一刀切静默。

验收示例：同一图片模型超时→右侧失败、HMI无技术错误；有效风险结果→HMI场景提醒、右侧记录对应输出；直接车控请求失败→无车辆动作、简短未完成反馈；无结果时不得显示风险解除/运行成功。
