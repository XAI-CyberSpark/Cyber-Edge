# 场景创作模型切换与生成检查

用户希望一句话生成有创意、可用、可信的座舱体验；本轮最新决定是增加模型选择，允许用 GPT、Claude 与 MiniMax 比较，不再继续只调 MiniMax 提示词。

交付：本地模型选择、提供商适配和统一生成检查流程。保留现有聊天与 HMI，设置按需打开，不新增测试控制台。换模型提供比较条件，不承诺换完即可解决开放场景质量。

| 需求 | 用户体验与验收 |
| --- | --- |
| REQ-1 选择模型 | 场景共创可选 MiniMax / GPT / Claude；当前模型可见。项目保存后保留选择；生成中不可切换。 |
| REQ-2 首次接入 | 未配置提供商打开设置，填写密钥与模型 ID；验证通过后保存并选择，失败或取消保留原选择与旧配置。 |
| REQ-3 真实路由 | 规格、构建、审查、修复均调用同一提供商；结果记录精确模型。无凭据/错误/超时明确失败，不调用别家替代。 |
| REQ-4 凭据边界 | 密钥仅服务端保存，不出现在项目、浏览器持久化、状态接口、错误响应；请求不能设置任意服务地址。 |
| REQ-5 统一检查 | 原始需求引用、能力覆盖、节点校验、内容规则、同模型内容审查、至多一次修复；失败不覆盖当前画布。 |
| REQ-6 试运行 | 支持的简单 authored 互动图由真实执行引擎隔离试跑；其他工作流明确尚未试跑，不冒充验证成功。 |
| REQ-7 运行连续性 | 新生成一般 LLM 节点绑定提供商，运行接口可路由 GPT/Claude；已有明确不同模型保持，图片识别独立。 |

默认模型 ID 是可编辑起点，不宣称当前最强或账户必然可用。配置验证会进行一次简短 API 调用，界面说明可能有少量费用。

非目标：代用户申请账号或购买额度、自动切换备选模型、修改儿童视觉识别模型、任意模型自动兼容、任意创新场景可靠性保证、真实车辆连接、多租户密钥托管。

后续：用户在页面配置 GPT/Claude 后，以同一生日航海原始需求分别生成，保留原始结果与失败，再比较可运行性、需求覆盖、文案/谜题正确性、延迟和成本。
