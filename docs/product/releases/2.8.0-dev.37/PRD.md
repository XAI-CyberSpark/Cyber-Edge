# 项目主文档与子文档管理

日期：2026-09-25。用户目标：有一个共同维护的主文档，管理设计规范、节点定义等知识，使项目可持续演进。

范围：升级既有 docs/README.md，明确主依据、状态、责任与更新规则；整理已有设计规范；连接节点、需求、版本和验收；让 AGENTS 要求后续任务读写这些记录；给历史文档标注适用范围。

非目标：重写所有历史 PRD、改 UI/节点运行、搬迁项目数据、建立后台自动同步、创建 Git 提交或发布。

验收：单一入口可到达核心文档，现有设计决策可查来源，草案/实现/历史证据明确区分，未完成事项不丢失，协作入口包含维护规则，受影响链接与版本指向一致。
